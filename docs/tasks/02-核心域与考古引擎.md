# 02 · 核心域与软件考古引擎（Python `packages/core`，前缀 T-CORE）

> 本栈是 ReviveOS 的灵魂：**Evidence First, AI Second**。考古引擎必须在完全不调用 LLM 的前提下独立产出环境基因（LLM 只做补强，见 T-AG 栈）。全部为纯 Python 逻辑，单元测试不依赖 Docker/网络（网络类客户端用录制夹具）。

### T-CORE-01 域模型与配置模块
- 背景：把 `schemas/` 四个契约映射为 pydantic v2 模型，供全仓复用；统一配置加载。
- 涉及文件：`packages/core/src/revive_core/models/{genome.py,events.py,manifest.py,score.py}`、`packages/core/src/revive_core/config.py`、`tests/unit/core/test_models.py`。
- 输入/输出契约：模型字段与 `schemas/*.json` 一一对应（用 `model_json_schema()` 反生成并与 schema diff）；config 用 `pydantic-settings`，命名空间 `REVIVE_*`，含《总览 §7》全部键；提供 `Config.load(env_file: Path | None)`。
- 验收：`uv run pytest tests/unit/core/test_models.py -q` 绿；`uv run python -c "from revive_core.config import Config; Config.load()"` 对每个必填敏感键缺失时给出字段级错误列表而非崩溃。
- 禁止：模型里不得出现业务逻辑/IO；不得用 `Optional` 掩盖 schema 中的 required。
- 依赖：T-INIT-01、T-INIT-02。

### T-CORE-02 仓库获取器（Git Fetcher）
- 背景：给定 GitHub URL，产出可考古的本地镜像（含完整历史、tags、可选 GitHub Releases 元数据）。
- 涉及文件：`packages/core/src/revive_core/archaeology/fetcher.py`、`tests/fixtures/repos/`（预生成的本地裸仓库夹具，生成脚本 `tests/fixtures/repos/make_fixtures.ps1|.sh` 二选一提交）。
- 输入/输出契约：`fetch_repo(url: str, dest: Path, *, github_token: str | None) -> RepoMirror`；`RepoMirror{path, default_branch, tags: list[TagInfo], branches, remotes, head_commit, cloned_at}`；仅允许 `github.com` 域名（白名单常量 `ALLOWED_GIT_HOSTS`）；`https://` 或既有本地路径；带 token 走 `Authorization` header 不落 URL；全 ref fetch（`--tags`），浅克隆禁止（历史即证据）。
- 验收：`uv run pytest tests/unit/core/test_fetcher.py -q` 绿（含：非法域名被拒、token 不出现在任何日志与 `.git/config` 断言）。
- 禁止：不得执行 `git` 以外的仓库内容操作；不得 `subprocess(shell=True)`。
- 依赖：T-CORE-01。

### T-CORE-03 清单文件证据抽取器
- 背景：静态解析一切声明运行环境的文件，输出结构化 `EvidenceItem`，是 genome 置信度的原料。
- 涉及文件：`packages/core/src/revive_core/archaeology/evidence.py`、`extractors/{requirements.py,setup_py.py,pyproject.py,pipfile.py,conda_env.py,dockerfile.py,ci_config.py}`、`tests/unit/core/extractors/`（每类 ≥3 夹具）。
- 输入/输出契约：`EvidenceItem{source_kind, reference: {file, line_start?, commit_sha?}, facts: dict}`；必覆盖：`requirements*.txt`（含 `-r` 展开一层、`extras`、环境标记）、`setup.py/setup.cfg`（`python_requires`、`install_requires`、classifiers 中的 `Programming Language :: Python :: 3.x`）、`pyproject.toml`（PEP621 + poetry 子集）、`Pipfile`、`environment.yml`、`Dockerfile` 的 `FROM`（含 tag 与多阶段首个非 builder）、`.github/workflows/*.yml` 的 `python-version` matrix、`.travis.yml`、`tox.ini` envlist。解析失败必须降级为 warning + `source_kind: inference` 空 facts，绝不中断。
- 验收：`uv run pytest tests/unit/core/extractors -q` 绿；对夹具 `py27-flask`（T-CORE-08）断言抽出 python_requires=="2.7" 与 flask 钉住版本。
- 禁止：不得用 LLM 解析；不得直接 `eval` setup.py 内容（用 AST）。
- 依赖：T-CORE-01（夹具断言部分待 T-CORE-08 就位后补齐）。

### T-CORE-04 Git 历史时间线考古
- 背景：同一份 requirements/pyproject 在不同年代的内容即"历史环境快照"。本工单产出按时间排列的依赖版本与运行时线索时间线。
- 涉及文件：`packages/core/src/revive_core/archaeology/timeline.py`、`tests/unit/core/test_timeline.py`。
- 输入/输出契约：`build_timeline(mirror: RepoMirror, watched_paths: list[str]) -> list[Snapshot]`；`Snapshot{commit_sha, date, author?, path_changes: dict[path, EvidenceItem]}`（对 watched path 每次变更抽取当时版本内容）；额外输出 `last_activity: date`、`death_candidates: list[(tag, date)]`（有 release tag 但后续无 commit）。数据全部来自 `git log --format` 流式解析（GitPython 或 git CLI 二选一，封装在内部）。
- 验收：夹具仓库 `three-era-deps`（同一 requirements.txt 跨 2015/2018/2021 三次变更）→ timeline 长度==3 且每段版本断言正确；`uv run pytest tests/unit/core/test_timeline.py -q` 绿。
- 禁止：不得把 commit message 全文塞进 facts（截断 ≤280 字符）。
- 依赖：T-CORE-02、T-CORE-03。

### T-CORE-05 PyPI 历史版本解析客户端
- 背景：判断"哪个版本在当年真实存在且兼容目标 Python"。查 PyPI JSON API（`https://pypi.org/pypi/<name>/json`）取全部 release 版本 + 每版本上传时间 + `requires_python`。
- 涉及文件：`packages/core/src/revive_core/archaeology/pypi_client.py`、`tests/unit/core/test_pypi_client.py`（respx 录制夹具）。
- 输入/输出契约：`versions_before(name: str, cutoff: datetime) -> list[Release]`、`Release{version, uploaded_at, requires_python}`；不存在的包返回空列表并记 `PackageNotFound` 日志；HTTP 层：超时 10s、指数退避重试 ≤3、缓存（本地 disk cache，key=包名，TTL 24h）；User-Agent 固定 `reviveos/<version>`。
- 验收：`uv run pytest tests/unit/core/test_pypi_client.py -q` 绿；断言：`numpy` 在 cutoff=2018-06-01 时不含 1.17+。
- 禁止：不得访问 PyPI 以外域名；不得并发 >5。
- 依赖：T-CORE-01。

### T-CORE-06 环境推断引擎（Genome Builder）
- 背景：把 C03/C04/C05 的证据加权合成为符合 `environment-genome.schema.json` 的推断结果。纯确定性规则引擎，可解释、可单测。
- 涉及文件：`packages/core/src/revive_core/archaeology/inference.py`、`rules.py`、`tests/unit/core/test_inference.py`。
- 输入/输出契约：`infer_genome(evidence: list[EvidenceItem], timeline, pypi: PypiClient) -> EnvironmentGenome`；规则表（写入 `rules.py` 常量并在报告引用）：Python 版本优先级 `python_requires > CI matrix > Dockerfile 基础镜像 tag > classifiers > README 关键词(标记 inference)`；依赖版本优先级 `lock 文件 > 钉住(==) > timeline 中最后活跃日期前 PyPI 最新版本 > 无版本(标记 inference)`；每条结论必须挂 ≥1 个 EvidenceItem；冲突证据 → confidence ≤0.7 且 `note` 说明冲突；`overall_confidence` = 各字段加权几何平均。
- 验收：三个黄金夹具分别断言：py27-flask → python 2.7 confidence≥0.9；modern-uvicorn → python≥3.9；ambiguous-readme → overall_confidence<0.7 且 inference 证据可见。`uv run pytest tests/unit/core/test_inference.py -q` 绿。
- 禁止：禁止调用任何 LLM；禁止输出 schema 之外字段（additionalProperties=false 自校验）。
- 依赖：T-CORE-03、T-CORE-04、T-CORE-05。

### T-CORE-07 错误分类器（Error Facts）
- 背景：沙箱内 build/run/test 的 stderr 需要被归类为可行动的结构化事实，Repair Agent 消费它。分类规则库与 R01–R08 死亡原因码对齐。
- 涉及文件：`packages/core/src/revive_core/errors/{taxonomy.py,classifiers.py}`、`tests/unit/core/test_classifiers.py`（每条规则一个真实报错文本夹具）。
- 输入/输出契约：`classify(stage: Build|Run|Test, stderr: str, exit_code: int) -> ErrorFact{category: enum[R01..R08 细分码], signature: str(规则名), suspect_files: list[str], hints: list[str], raw_excerpt: str}`；最少覆盖规则：`ImportError/cannot import name`（含 collections.abc 案例）、`ModuleNotFoundError`、`No matching distribution found`、`pip ResolutionImpossible`、`gcc/undefined reference`、`missing shared library (libX.so)`、`python version incompatible (Requires-Python)`、`SyntaxError 指向 py2 print/except 语法`、`numpy ABI mismatch`、超时 `R99`。`signature` 全局唯一稳定（当合同用，不得随版本改名）。
- 验收：`uv run pytest tests/unit/core/test_classifiers.py -q` 绿；未知错误必须落 `category=UNKNOWN` 且 `signature="fallback"`。
- 禁止：不得用正则做跨行灾难回溯（线性扫描即可，处理 1MB 日志 <200ms，加基准断言）。
- 依赖：T-CORE-01。

### T-CORE-08 黄金夹具仓库集（跨栈测试基座）
- 背景：全仓需要一个可重复构建的"死项目样本集"，覆盖 R01–R08，供 core/agents/sandbox/bench 各栈测试复用。
- 涉及文件：`tests/fixtures/dead_projects/`（每个项目的源 + `build.ps1|.sh` 用 git init 打 tag 重放历史）、`manifest.json`（每夹具：预期 genome、预期错误类别、许可证）。
- 输入/输出契约：首批 9 个夹具：`py27-flask`、`tf1-keras-legacy`（依赖消失）、`numpy-abi`（ABI 断链）、`collections-abc`（py3.10 移除）、`removed-index`（requirements 指向已死私有源）、`healthy-baseline`（对照组，本就能跑）、`three-era-deps`（requirements 跨 2015/2018/2021 三时代变更，供 T-CORE-04）、`modern-uvicorn`（py≥3.9 黄金路径，供 T-CORE-06）、`ambiguous-readme`（证据冲突低置信样本，供 T-CORE-06）。每个必须含 3+ 提交、2+ tag、真实 git 日期（用 `GIT_AUTHOR_DATE` 伪造历史）。
- 验收：脚本从零生成 9 仓库 → 对每个跑 T-CORE-06 的 `infer_genome`，结果与 `manifest.json` 预期一致（允许 confidence ±0.05）。
- 禁止：夹具不得含任何真实凭据/私有代码；git 历史日期必须可复现（固定值）。
- 依赖：T-CORE-02（可与 C03–C06 并行开发）。

### T-CORE-09 CLI `revive analyze`（本地模式，M1 里程碑）
- 背景：第一条用户可见命令：仓库 URL → 考古 → 打印 genome 表 + 证据链；同时作为后续所有 CLI 的骨架（typer app、全局 flags、日志）。
- 涉及文件：`cli/src/revive_cli/main.py`（typer 根 + `analyze`）、`cli/src/revive_cli/render.py`（rich 表格）、`tests/integration/cli/test_analyze.py`。
- 输入/输出契约：`revive analyze <url> [--out genome.json] [--offline]`；`--offline` 跳过 T-CORE-05 网络（置信度相应降级并显示提示）；输出必须符合 genome schema（`--out` 落盘文件用 jsonschema 自校验）；退出码：0 成功 / 2 仓库不可达 / 3 证据不足（overall_confidence<0.4）。
- 验收：`uv run revive analyze tests/fixtures/dead_projects/py27-flask/.git --offline` 打印 python 2.7 行且退出 0；`uv run pytest tests/integration/cli/test_analyze.py -q` 绿。
- 禁止：CLI 内不得实现考古逻辑（只能编排 `revive_core`）；不得打印堆栈给终端用户（统一错误面板）。
- 依赖：T-CORE-06、T-CORE-08。
