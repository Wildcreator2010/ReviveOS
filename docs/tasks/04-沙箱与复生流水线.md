# 04 · 沙箱执行与复生流水线（Docker/胶囊/评分/CLI 完整体，前缀 T-SB / T-CAP / T-CLI）

> 安全基线（全部工单继承）：目标代码只存在于沙箱容器内；运行期容器一律 `network_disabled=true, user="1000:1000", no_new_privileges, tmpfs=/tmp:rw,size=256m`；唯一允许出网的阶段是"构建期依赖安装"，且目标域名白名单固定为 `pypi.org / files.pythonhosted.org / repo.anaconda.com / registry-1.docker.io / auth.docker.io / production.cloudflare.docker.com`。

### T-SB-01 历史环境镜像矩阵与构建器
- 背景："先创造一个过去的世界"。根据 genome 生成历史运行时镜像（Ubuntu 14.04–22.04 × Python 2.7/3.5–3.12；Python 2.7 走 conda 路线，deadsnakes 覆盖 3.x）。
- 涉及文件：`packages/core/src/revive_core/sandbox/image_matrix.py`、`dockerfile_template.py`、`infra/sandbox/base-py*.Dockerfile.tpl`、`tests/unit/sandbox/test_image_matrix.py`。
- 输入/输出契约：`plan_image(genome) -> ImagePlan{os_image(带 digest 期望), python_install: apt|conda|source, extra_apt: list, conda_env_yaml?}`；矩阵表是数据不是 if-else（`image_matrix.py` 内单一 `MATRIX` 常量）；无法命中矩阵返回 `Unsupported` 并列出最接近的 3 个候选（供人工/Agent 决策）；模板渲染用 Jinja2，禁止字符串拼接注入（genome 字段过 `shlex.quote` 级清洗）。
- 验收：`uv run pytest tests/unit/sandbox/test_image_matrix.py -q` 绿（含 py2.7→conda、ubuntu18.04+py3.6→deadsnakes、ubuntu14.04+py3.4→source 三条黄金路径与一条 Unsupported）；人工检查点：任选一行矩阵在本地 `docker build` 成功。
- 禁止：不得引入非官方基础镜像源；模板中不得出现 `RUN curl | sh`。
- 依赖：T-CORE-06。

### T-SB-02 ExecutionPort 的 Docker 实现
- 背景：实现 T-AG-06 定义的抽象端口：容器全生命周期 + 工作区快照/恢复。
- 涉及文件：`packages/core/src/revive_core/sandbox/executor.py`、`port_impl.py`、`tests/integration/sandbox/test_executor.py`（标记 `requires_docker`）。
- 输入/输出契约：`ensure_env(genome)->SandboxHandle{container_id, ws_path, digest}`；`run(kind, argv, timeout)->RunResult{exit_code, stdout_ref, stderr_ref, duration}`（stdout/stderr 流式写入 artifacts 目录并算 sha256，不整段驻内存 >8MB 缓冲）；`apply_patch(diff)->ok|PatchConflict`（容器内 `git apply --check` 先行）；`snapshot_ws()/restore_ws(token)` 用 tar 流；容器命名 `revive-sbx-<job_id>-<n>`，带 label `revive.job_id` 便于孤儿清扫；`close()` 幂等销毁。
- 验收：`uv run pytest tests/integration/sandbox/test_executor.py -q` 在有 Docker 环境全绿；快照→改 3 个文件→恢复→hash 与快照前一致；超时 5s 的 `sleep 30` 被 kill 且 RunResult.exit_code==-1；`docker ps -a --filter label=revive.job_id` 在测试结束后为空（清扫断言）。
- 禁止：禁止 `privileged`、禁止挂载宿主 `/` 或 `~`；docker socket 权限仅限控制面进程环境。
- 依赖：T-SB-01、T-AG-06（仅依赖其 Port 定义接口文件，可并行开发后合对）。

### T-SB-03 依赖安装引擎（历史版本回溯安装）
- 背景：死软件复活的第一道鬼门关是 `pip install` 装不上。按 genome 的依赖候选做"逐版本回退"安装直至解析成功，生成 `dependencies.lock`。
- 涉及文件：`packages/core/src/revive_core/sandbox/dep_solver.py`、`tests/integration/sandbox/test_dep_solver.py`。
- 输入/输出契约：`resolve_and_install(handle, genome) -> InstallOutcome{locked: list[PinnedDep], fallbacks_used: int, failures: list[(name, tried_versions)]}`；候选顺序：钉住版本 → T-CORE-05 的历史版本（按项目最后活跃日期）→ 次旧版本（≤3 次回退）；每次 pip 调用产 `build.attempt` 事件；输出 lock 记录 `installed_version` 与 `original_declared_version` 的差异（复生报告要展示"我们改动了什么"）。
- 验收：夹具 `collections-abc`（声明 numpy==1.16.4）在 py3.8 镜像内装不上时自动回退并如实记录；`uv run pytest tests/integration/sandbox/test_dep_solver.py -q` 全绿（`requires_docker`）。
- 禁止：禁止升级到高于原声明的大版本（现代化红线）；禁止 `--pre`；禁止非白名单 index。
- 依赖：T-SB-02、T-CORE-05。

### T-SB-04 构建/运行/测试 Runner 与错误接线
- 背景：把 build→run→test 三类执行统一为流水线步骤，失败喂给 T-CORE-07 分类器并发事件，形成 supervisor 需要的失败分支数据。
- 涉及文件：`packages/core/src/revive_core/sandbox/runner.py`、`tests/integration/sandbox/test_runner.py`。
- 输入/输出契约：`run_stage(handle, stage: build|test|cli_smoke, plan) -> StageResult{ok, error_fact|None, artifacts}`；build 步骤=`pip install -e .`，test=`pytest -x -q`（无 tests 目录时降级为 `python -m <pkg>` import 冒烟并在结果标记 `tests_absent=true`）；`StageResult.error_fact` 必须是 T-CORE-07 `ErrorFact`；事件字段与 `job-event` payload oneOf 分支对齐。
- 验收：夹具矩阵：`healthy-baseline` 全 stage ok；`collections-abc` 首轮 build ok 但 import 阶段报 `cannot import name 'Mapping'` 且 `error_fact.signature` 命中预期规则；`uv run pytest tests/integration/sandbox/test_runner.py -q` 全绿。
- 禁止：runner 不得做任何修复决策（那是 T-AG 的事）。
- 依赖：T-SB-02、T-SB-03、T-CORE-07。

### T-SB-05 修复环路集成（Patch 应用与回滚）
- 背景：把 T-AG-04 的 `PatchProposal` 在沙箱内落地/回滚，闭合 M2 里程碑（build→失败→修复→build 成功）。
- 涉及文件：`packages/core/src/revive_core/sandbox/patch_flow.py`、`tests/integration/sandbox/test_patch_flow.py`。
- 输入/输出契约：`apply_and_verify(handle, proposal, rerun: Callable) -> PatchOutcome{applied: bool, snapshot_token, rerun_result, rolled_back: bool}`；先 `snapshot_ws()` 再 `apply_patch` 再 rerun；rerun 失败 → `restore_ws` 并返回 `rolled_back=true`；成功 → 把 diff 追加到 `patches/patch-<seq>.diff` 列表（内存对象，胶囊在 T-CAP-02 落盘）。
- 验收：golden E2E（本地 Docker + fake LLM 回放固定 diff）：`collections-abc` 夹具由红转绿，`revive resurrect --local` 输出 M2 事件序列；`uv run pytest tests/integration/sandbox/test_patch_flow.py -q` 全绿。
- 禁止：禁止跳过 rerun 直接信任 diff；禁止同一 patch 重复应用（幂等 token）。
- 依赖：T-SB-04、T-AG-04。

### T-SB-06 行为指纹采集与等价比对
- 背景："复生后还是不是原软件"的量化答案。执行 BehaviorPlan 采集指纹，与原行为基线比对得 `behavior.compatibility`。
- 涉及文件：`schemas/behavior-fingerprint.schema.json`（新增第五契约，附正反例夹具）、`packages/core/src/revive_core/behavior/{capture.py,compare.py}`、`tests/unit/behavior/test_compare.py`。
- 输入/输出契约：`capture(handle, plan) -> Fingerprint{cases: [{id, exit_code, stdout_hash, stdout_excerpt_hash?, output_files: [{glob, sha256}], numeric_series?: [{name, values, dtype}]}]}`；`compare(baseline, after, tolerances) -> BehaviorResult{compatibility: 0..1, per_case: [...], drifted_fields}`；三种容差模式：exact（hash 相等）、numeric（逐元素 `|a-b| ≤ eps_abs + eps_rel×|b|`）、structural（JSON 键树同形且叶子按容差）；**基线来源优先级**必须实现并记录于 provenance：① 目标仓库自带期望输出文件 ② 原 tag 在可运行的老镜像里现场采集（先跑原版！）③ 论文/README 声明值（人工录入通道）。无法建立基线 → `compatibility=null` 且评分分量按契约降级规则处理（不得伪造 1.0）。
- 验收：`uv run pytest tests/unit/behavior/test_compare.py -q` 绿（含 numeric 容差边界用例）；集成：`healthy-baseline` 跑两次 plan → compatibility==1.0；人为注入数值扰动 → 0<compatibility<1 且 drifted_fields 指名道姓。
- 禁止：比对逻辑不得依赖 LLM；指纹里不得存用户数据原文（只存 hash/excerpt 哈希）。
- 依赖：T-SB-02、T-AG-05。

### T-CAP-01 Resurrection Score 计算器
- 背景：六分量加权评分（权重在 `resurrection-score.schema.json` 的 `x-weights`），全系统唯一评分实现，CLI/Web/Bench 共用。
- 涉及文件：`packages/core/src/revive_core/scoring.py`、`tests/unit/core/test_scoring.py`。
- 输入/输出契约：`compute_score(runtime_ok, deps_ratio, build_ok, tests_pass_ratio, behavior_compat|None, repro_verified) -> ResurrectionScore`；缺行为基线时 `behavior` 分量按 `x-weights` 中定义的降级权重重新归一（规则写进 schema 注释并在代码中同源读取）；输出必须通过 schema 自校验；状态映射：total≥85 且 repro→`alive`；60–84 或 behavior=null→`partial`；<60→`dead`。
- 验收：`uv run pytest tests/unit/core/test_scoring.py -q` 绿，含边界 85/60 与 null 行为基线两例。
- 禁止：不得在 CLI/Web 内另写一份公式。
- 依赖：T-INIT-02、T-SB-06。

### T-CAP-02 `.revive` 胶囊构建器
- 背景：复生的最终交付物。按《方案 §6》目录布局打包 tar.zst，内容寻址、可复算。
- 涉及文件：`packages/core/src/revive_core/capsule/{builder.py,layout.py}`、`tests/unit/capsule/test_builder.py`。
- 输入/输出契约：`build_capsule(run_state) -> Path`；布局固定：`manifest.json`（schema 校验）/`source.tar`（原始 commit 全量）/`environment.json`（genome 冻结版）/`dependencies.lock`/`docker/Dockerfile.resurrected`/`tests/`（BehaviorPlan+用例）/`behavior/fingerprints.json+traces/`/`sbom/sbom.json`（在工具容器内跑 Syft 生成 CycloneDX，禁止宿主机安装）/`patches/*.diff`/`metadata/{provenance.json,resurrection-report.json,llm-traces.jsonl}`；所有条目 sha256 写入 manifest；同一 run_state 两次构建字节级一致（时间戳取 run 起点、tar 排序固定、gzip→zstd level 固定）。
- 验收：`uv run pytest tests/unit/capsule/test_builder.py -q` 绿（含双构建 hash 相等断言、manifest schema 校验、patches 与 provenance 完整性）；`revive resurrect --local` 对 `healthy-baseline` 产出的 `.revive` 用 `tar --list` 顺序稳定。
- 禁止：胶囊内不得含 LLM API Key、宿主绝对路径、`.git` 全局配置；不得收录许可证明确禁止再分发的原文件（标记 `redistribute=false` 仅存引用）。
- 依赖：T-CAP-01、T-SB-05、T-SB-06、T-AG-07。

### T-CAP-03 `revive verify` / `revive replay`（胶囊可复现性验收）
- 背景："Preserve"承诺的机器证明：换一台干净 Docker 环境，凭胶囊重建镜像并重跑行为用例。
- 涉及文件：`packages/core/src/revive_core/capsule/{verify.py,replay.py}`、`cli` 子命令注册、`tests/integration/capsule/test_verify.py`。
- 输入/输出契约：`verify(capsule) -> VerifyReport{manifest_ok, digests_ok, docker_rebuild_ok, behavior_rematch: bool, score_reproduced: float|None}`；顺序：schema 校验→逐文件 sha256→`docker build -f docker/Dockerfile.resurrected`→在 network_disabled 容器内重跑 `tests/` 用例→比对 `behavior/fingerprints.json`；退出码 0/1/2（结构损坏/行为漂移/构建失败）；`replay` 交互式进容器（TTY 分配）。
- 验收：`uv run revive verify out-healthy.revive` 输出全 ok 退出 0；篡改胶囊内任一文件 1 字节后退出码非 0 且指名文件；`uv run pytest tests/integration/capsule/test_verify.py -q` 全绿（`requires_docker`）。——M3 里程碑达成。
- 禁止：verify 不得联网重建（依赖必须在构建期已烘进镜像层，允许 `--allow-index` 显式豁免并写入报告）。
- 依赖：T-CAP-02。

### T-CLI-01 服务端模式命令组（login/resurrect --server/jobs）
- 背景：生产 CLI 默认作为 ReviveOS 控制台的瘦客户端：鉴权、提交任务、订阅事件流、下载胶囊。
- 涉及文件：`cli/src/revive_cli/{auth.py,jobs.py,sse.py,client.py}`、`tests/integration/cli/test_server_mode.py`。
- 输入/输出契约：`revive login`（浏览器授权回跳或 token 粘贴双路径）；`revive resurrect <url> [--server URL]` 提交后流式渲染事件（rich Live，16 类事件全覆盖，未知类型降级为原样 JSON 行）；`revive jobs ls/get <id>`、`revive download <job_id> -o file.revive`（presigned URL）；client 由 OpenAPI 生成码为基（依赖 T-BE-03 导出物，先以 httpx 手写层+契约测试占位）；401 自动 refresh 一次重试。
- 验收：对着 dev compose 起的服务：`uv run revive resurrect https://github.com/<fixture> --server http://localhost:8000` 事件流实时渲染且落 `job.succeeded`；`uv run pytest tests/integration/cli/test_server_mode.py -q` 绿（respx mock + 一个 against-live 标记测试）。
- 禁止：CLI 不得把 token 写入 shell history 可见位置（存 OS keyring，失败降级 `~/.revive/credentials.json` 权限 0600 并警告）。
- 依赖：T-CORE-09、T-BE-03（接口冻结后可先行 mock 开发）。

### T-CLI-02 `revive resurrect --local` 全链路装配（M2/M3 合体）
- 背景：本地模式：无服务端、单机 Docker，直接以 LangGraph + ExecutionPort 跑完整链路，产出胶囊。这是给工程师信任的"透明模式"。
- 涉及文件：`cli/src/revive_cli/local_pipeline.py`、`tests/integration/cli/test_local_e2e.py`。
- 输入/输出契约：装配 supervisor（SQLite/内存 checkpointer 替代 PG）+ 本机 docker executor；`--budget-usd/--timeout/--keep-sandbox` 透传；结束时打印总面板：事件时间线、score 六分量条形、胶囊路径与 `revive verify` 提示。
- 验收：`uv run revive resurrect --local tests/fixtures/dead_projects/collections-abc/.git`（配 fake LLM provider env）完成修复环路并出胶囊；`uv run revive verify <产物>` 退出 0；`uv run pytest tests/integration/cli/test_local_e2e.py -q` 全绿（`requires_docker`）。
- 禁止：local 模式不得静默联网拉 PyPI 以外的源；不得复用服务端密钥。
- 依赖：T-SB-05、T-CAP-03、T-AG-06。
