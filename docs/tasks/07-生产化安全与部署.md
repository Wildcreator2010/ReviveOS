# 07 · 生产化：安全、可观测、部署（前缀 T-PRD）

> 本栈把"能跑"变成"敢上线"。核心资产威胁模型：① 任意用户代码在自家服务器执行（沙箱逃逸）② 服务器被诱导访问内网/任意 URL（SSRF）③ 凭据泄漏（LLM key、DB）。每条工单的验收必须包含对应的攻击性测试。

### T-PRD-01 生产沙箱加固
- 背景：dev 沙箱只做了断网+限额；生产需叠加：只读根文件系统、seccomp、digest 锁、无特权用户映射、镜像预扫。
- 涉及文件：`infra/sandbox/seccomp.revive.json`、`packages/core/src/revive_core/sandbox/hardening.py`（统一 HostConfig 工厂）、`tests/integration/sandbox/test_hardening.py`、`docs/threat-model.md`（沙箱一节）。
- 输入/输出契约：运行容器强制 `read_only=True + tmpfs(/tmp,/workspace)`、`security_opt=["no-new-privileges", "seccomp:revive"]`、`cap_drop=["ALL"]`、`pids_limit=256`、基础镜像一律 `image@sha256:` 引用（构建期解析 tag→digest 并冻结进胶囊 manifest）；逃逸冒烟测试：fork 炸弹、写 `/etc`、`mount`、域 socket 访问 4 个用例必须全被拒。
- 验收：`uv run pytest tests/integration/sandbox/test_hardening.py -q` 全绿；`docker inspect` 抽查确认配置生效；威胁模型文档更新。
- 禁止：禁止 `--privileged`、禁止 docker.sock 挂进沙箱容器、禁止放开 `CAP_SYS_ADMIN`。
- 依赖：T-SB-02。

### T-PRD-02 SSRF 与输入防线（控制面出网收口）
- 背景：`POST /projects` 与 worker clone 都会以服务端身份访问外部 URL——这是最大的非沙箱攻击面。
- 涉及文件：`packages/core/src/revive_core/netguard.py`、`apps/api` 校验接线、`tests/integration/api/test_ssrf.py`。
- 输入/输出契约：全系统服务端出网只允许两个用途：① github.com 仓库（API 元数据 + clone）② 依赖安装白名单（T-SB 头部声明的域名）；`netguard.assert_safe_url(url)`：解析主机→拒私网/回环/链路本地/云元数据 IP（169.254.169.254）、拒重定向跟随（或重定向后二次校验）、拒非常规端口、拒 `ext::`/`fd::` 等 git 传输后门 scheme；DNS 解析后校验 IP（防 DNS rebinding：解析→连接前二次解析比对或固定 IP 连接）。
- 验收：`uv run pytest tests/integration/api/test_ssrf.py -q` 绿（含：`http://127.0.0.1:5432`、metadata IP、重定向到私网、`ext::sh -c` 四攻击用例全 400）；人工检查：日志不含被拒 URL 的 query 片段。
- 禁止：禁止白名单外任何 URL 由服务端发起（包括"用户粘贴的历史 wheel 链接"这类需求→引导走沙箱内构建期安装）。
- 依赖：T-BE-03。

### T-PRD-03 密钥与环境治理
- 背景：生产 env 集中定义、启动校验、轮转手册。
- 涉及文件：`infra/envs/revive.prod.env.template`（值全占位）、`apps/api/src/revive_api/config_check.py`（启动自检）、`docs/runbook-secrets.md`。
- 输入/输出契约：启动时校验：必填键存在、JWT secret ≥32 字节且非默认值、MinIO 桶存在、`REVIVE_ENV=prod` 时禁用 debug 开关（`REVIVE_DEBUG_LLM` 必须关）；违规直接拒绝启动并列明键名（不列值）；轮转手册覆盖：LLM key / JWT / MinIO / API Key 四类。
- 验收：`uv run python -c "from revive_api.config_check import ensure_prod; ensure_prod({'REVIVE_ENV':'prod','REVIVE_JWT__SECRET':'short'})"` 非零退出且信息含 `REVIVE_JWT__SECRET`；compose prod（T-PRD-06）用 template 生成 env 后 API 正常启动。
- 禁止：template 文件禁止含任何真实值；禁止 env 值写进任何日志/tracing。
- 依赖：T-BE-04。

### T-PRD-04 OpenTelemetry 链路与核心指标
- 背景：一次 resurrect = 一条跨 API→Celery→LangGraph→LLM→沙箱的 trace；上线要有 SLI。
- 涉及文件：`infra/observability/otel-collector.yml`、各进程 instrumentation 接线、`apps/api/src/revive_api/metrics.py`、`tests/unit/api/test_metrics.py`。
- 输入/输出契约：指标最少集：`revive_jobs_total{outcome}`、`revive_job_duration_seconds`（直方图）、`revive_sandbox_runs_total{stage}`、`revive_llm_cost_usd_total{provider,model}`、`revive_repair_success_ratio`；`/metrics` 端点仅内网/basic auth；trace 属性含 job_id/project_id（无仓库 URL 明文）；LLM 适配器与 supervisor 已在 T-AG 留 span 位，此处接通 collector。
- 验收：跑一次 fixture job 后 `curl :9090/metrics`（经 collector/prometheus）能查到上述 5 项且计数增加；Jaeger（compose 内轻量替身即可）能看到一条含 ≥6 个 span 的完整 trace。
- 禁止：指标 label 禁止高基数字段（job_id 只做 trace 属性，不做 metric label）。
- 依赖：T-BE-05、T-AG-07。

### T-PRD-05 日志聚合与保留策略
- 背景：structlog JSON → Loki；Grafana 预置面板（流水线健康、错误签名 Top、成本）；PII 清洗；保留 dev 7 天 / prod 30 天。
- 涉及文件：`infra/observability/{loki.yml,promtail.yml,grafana/provisioning/*}`、`packages/core/src/revive_core/logging.py`（redaction filter）、`docs/runbook-logs.md`。
- 输入/输出契约：所有服务 stdout JSON 单行；redaction：正则剥 `sk-/ghp_/Bearer` 与邮箱本地部分；grafana dashboard JSON 入库版本化；三条排障查询模板（按 job_id 追事件 / 按 signature 聚合构建失败 / 成本按日）。
- 验收：`docker compose` 起观测栈后，故意触发一次带 key 的失败，Loki 查询确认该行密钥已脱敏；dashboard 载入无报错。
- 禁止：禁止把 raw 用户代码 stdout 全量进日志（引用 artifact 指针）。
- 依赖：T-PRD-04。

### T-PRD-06 prod compose 全栈编排与 TLS
- 背景：单机生产入口：api、worker、beat、web、postgres、redis、minio、caddy、otel 栈一键起；健康依赖顺序、卷持久化、资源上限。
- 涉及文件：`infra/compose/prod.docker-compose.yml`、`infra/compose/caddy/Caddyfile`、`Dockerfile.api`、`Dockerfile.worker`、`Dockerfile.web`（多阶段、非 root、digest pin）、`docs/runbook-deploy.md`。
- 输入/输出契约：所有服务 `restart: unless-stopped` + healthcheck + `depends_on: condition: service_healthy`；数据卷 pg/redis/minio 显式命名卷；worker 才挂 docker.sock（且配 T-PRD-01 的 host config）；caddy 终结 TLS（自动证书）仅转发 web/api；`make deploy-prod` = pull→migrate（一次性 job）→up→冒烟 `curl /readyz`。
- 验收：全新目录 `docker compose -f prod... up -d` → `curl https://localhost/readyz`（自签或本地域名）全 ok；compose 配置静态扫描 `docker compose config --quiet`；`make deploy-prod` 幂等可重跑。
- 禁止：生产 compose 禁止端口 5432/6379/9000 暴露公网；禁止 `network_mode: host`。
- 依赖：T-BE-*、T-FE-01、T-PRD-01..05。

### T-PRD-07 备份与恢复演练
- 背景：胶囊与事件是资产：pg 定时 dump + MinIO 版本化/镜像；恢复必须演练过才算存在。
- 涉及文件：`infra/backup/{pg-backup.sh,minio-sync.sh,systemd timers 或 beat 任务}`、`docs/runbook-restore.md`、`tests/ops/restore_drill.sh`。
- 输入/输出契约：每日全量 pg_dump（zstd）+ WAL 归档或简化为每日两次（说明 RPO）；minio mc mirror 到第二桶/卷；演练脚本：临时起新栈→恢复→跑 `revive verify` 对备份期内所有胶囊抽样→输出 PASS 清单。
- 验收：本地执行 `bash tests/ops/restore_drill.sh` 退出 0（含"备份被删除后重建再验证"路径）；RPO/RTO 数字写入 runbook（来自演练实测，禁止拍脑袋）。
- 禁止：备份介质与生产同卷同机不算备份（至少在文档中给出异地选项）。
- 依赖：T-PRD-06。

### T-PRD-08 供应链 CI：镜像构建、扫描、SBOM 与制品
- 背景：自身也要可追溯：ReviveOS 自己的每个发布镜像附 SBOM + 漏洞门禁 + 制品校验和。
- 涉及文件：`.github/workflows/release.yml`、`tools/image_digests.py`（锁定矩阵 digest 更新 PR）、`docs/release-process.md`。
- 输入/输出契约：release 流水线=构建三镜像→trivy 门禁（high/critical=0 或列例外清单）→syft 出 SBOM 附到 release→digests 写入 `image_matrix.py` 的锁文件→CLI 产物 `revive` wheel sdist + sha256；版本号单一来源（根 pyproject），tag 触发。
- 验收：手动触发 workflow 全绿并产出三镜像 digest + SBOM 附件；`uv run pytest tests/unit/sandbox/test_image_matrix.py -q` 在 digest 锁文件缺失时失败（证明锁生效）。
- 禁止：禁止 CI 里以明文传任何 registry 凭据以外的云密钥。
- 依赖：T-PRD-06。

### T-PRD-09 负载冒烟与故障演练
- 背景：上线前知道系统怎么死：并发压测 + 关键依赖故障剧本 + 降级预期。
- 涉及文件：`tests/ops/load/k6_resurrect.js`、`tests/ops/chaos/{kill_worker.sh,redis_down.sh,pg_down.sh}`、`docs/runbook-incidents.md`。
- 输入/输出契约：k6 剧本：50 并发提交（fake LLM）→ 断言：配额正确拒绝超额、无孤儿沙箱、P95 API 延迟阈值写入文档；三个故障剧本各定义"预期行为"（worker 死→job 重投或标 failed 不悬挂；redis 死→SSE 断但 API 可用；pg 死→readyz 503 全站维护态）并验证。
- 验收：`bash tests/ops/chaos/kill_worker.sh` 等三脚本按预期结果退出 0；incidents runbook 含每条剧本的观测查询（复用 T-PRD-05 模板）。
- 禁止：压测禁止打生产 GitHub API（用 mock/缓存层）。
- 依赖：T-PRD-06。
