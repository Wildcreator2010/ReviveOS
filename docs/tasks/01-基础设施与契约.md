# 01 · 基础设施与契约（T-INIT 栈）—— 全部可立即派发，串行执行

> 本栈是所有后续工单的地基。完成标准：任何 LLM 拿到后续任一栈的工单，不用再问仓库结构问题。

### T-INIT-01 建立 monorepo 骨架与统一任务入口
- 背景：按《总览 §3》创建仓库骨架。所有 Python 子包用 uv workspace 管理；`apps/web` 暂只留 pnpm 脚手架占位（前端工单再展开）。
- 涉及文件：`pyproject.toml`（workspace 根）、`cli/pyproject.toml`、`packages/core/pyproject.toml`、`agents/pyproject.toml`、`apps/api/pyproject.toml`、`Makefile`、`.gitignore`（含 `.env*`、`*.revive`、`node_modules`）、`.python-version`(3.11)、`uv.lock`、各包 `src/` 空 `__init__.py` + 一个可导入哨兵测试 `tests/test_imports.py`。
- 输入/输出契约：Makefile 目标固定为 `dev test lint typecheck migrate fmt`（dev 在 T-INIT-04 前允许 echo "not yet"）。
- 验收：`uv sync --all-packages` 退出码 0；`uv run pytest tests/test_imports.py -q` 通过；`uv run python -c "import revive_core, revive_cli, revive_agents, revive_api"` 成功。
- 禁止：不得引入 poetry/flit；不得建任何业务代码。
- 依赖：可立即派发。

### T-INIT-02 四大核心 JSON Schema 契约定稿
- 背景：`.revive` manifest、环境基因、任务事件、复生评分是跨栈唯一事实来源（字段详表见《总览 §4》）。本工单只写 schema 与校验测试，不写任何语言实现。
- 涉及文件：`schemas/revive-manifest.schema.json`、`schemas/environment-genome.schema.json`、`schemas/job-event.schema.json`、`schemas/resurrection-score.schema.json`、`tests/contracts/test_schemas.py`（每 schema 至少 1 个正例 + 2 个应被拒绝的反例夹具 `tests/contracts/fixtures/`）。
- 输入/输出契约：Draft 2020-12；`job-event` 的 `type` 用 `enum` 固定 15 值；`resurrection-score` 用 `required` 锁死六分量且权重常量写入 schema `x-weights`；manifest 的 `status` 枚举 `["alive","partial","dead"]`；genome 每个推断字段必含 `confidence: number 0..1` 与 `evidence: array`（元素含 `source_kind ∈ {git_history, manifest_file, ci_config, doc, release_artifact, inference}`、`reference`、`note?`）。
- 验收：`uv run pytest tests/contracts -q` 全绿；`uv run python -c "import jsonschema, json, pathlib as p; [jsonschema.Draft202012Validator.check_schema(json.loads(f.read_text())) for f in p.Path('schemas').glob('*.json')]"` 退出 0。
- 禁止：不得用 `additionalProperties: true` 打开未知字段（manifest/genome/score 一律 `false`，事件 `payload` 按 type 用 `oneOf` 分支收敛）。
- 依赖：T-INIT-01。

### T-INIT-03 CI 流水线与 pre-commit
- 背景：把《总览 §1/§6/§7》的质量红线变成机器闸门。
- 涉及文件：`.github/workflows/ci.yml`、`.pre-commit-config.yaml`、`tools/check_global_rules.py`。
- 输入/输出契约：CI 步骤= ruff check+format --check → mypy（core/cli/agents/api 四包）→ pytest 单元层 → jsonschema 契约测试 → `check_global_rules.py`（扫描：代码中疑似密钥的正则、`max_iterations`等常量未被篡改、Agent 修复权限常量存在且 ≤ 全局值）。门禁失败即红。
- 验收（本地等效）：`uv run pre-commit run --all-files` 与 `uv run python tools/check_global_rules.py .` 均退出 0；故意在 `cli/src/revive_cli/__init__.py` 塞一行 `API_KEY="sk-abcdef123456"` 后 `check_global_rules.py` 必须非零退出（测完还原）。
- 禁止：CI 不得配置任何部署步骤（部署属于 T-PRD 栈）；不得 skip 任何 hook。
- 依赖：T-INIT-01、T-INIT-02。

### T-INIT-04 Windows 开发环境引导（Docker Desktop/WSL2）与 dev compose
- 背景：开发机是 Windows，重任务全依赖 Docker。先把环境固定：WSL2 后端 Docker Desktop、compose 起 pgvector/redis/minio 三件套 + `make dev`。
- 涉及文件：`infra/compose/dev.docker-compose.yml`、`docs/dev-setup-windows.md`、`Makefile`（dev 目标实装）、`.env.example`（同步《总览 §7》，密钥值一律空）。
- 输入/输出契约：服务名与端口固定 `postgres:5432 redis:6379 minio:9000/9001`；pgvector 镜像用 `pgvector/pgvector:pg16`；MinIO 默认桶 `capsules`、`artifacts`。
- 验收：`docker compose -f infra/compose/dev.docker-compose.yml up -d` → `docker compose -f ... exec postgres psql -U revive -c "select 1"` 返回 1 → `make dev` 三容器 healthy；文档含 WSL2 下 Windows 路径挂载（`/c/Users/...`）与 `:ro` 权限常见坑各 ≥2 条。
- 禁止：不得把 `cap_add: [SYS_ADMIN]` 等特权写进 dev compose；不得硬编码主机绝对盘符以外的用户隐私路径。
- 依赖：T-INIT-01。
