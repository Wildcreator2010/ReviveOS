# 03 · AI 智能体与模型接入（Python `agents`，LangGraph，前缀 T-AG）

> 红线：AI 不直接落地任何修改——所有 Patch 必须过 校验→沙箱 Build→Test 三环，失败即回滚。模型供应商对用户透明（OpenAI/Anthropic/custom），代码内绝不写死供应商名与模型名。

### T-AG-01 LLM Provider 抽象层
- 背景：全系统唯一的大模型出口。用户通过 `REVIVE_LLM__*` 环境变量自选 openai / anthropic / custom（OpenAI 兼容 base_url）。
- 涉及文件：`agents/src/revive_agents/llm/{base.py,openai_adapter.py,anthropic_adapter.py,fake.py}`、`agents/src/revive_agents/llm/factory.py`、`tests/unit/agents/test_llm.py`。
- 输入/输出契约：`class LLMProvider(Protocol)`：`async def complete(messages, *, response_format: JSONSchema | None, max_tokens, temperature, timeout) -> Completion{text, json: dict, usage: Usage{input_tokens,output_tokens,cost_usd_estimate}, raw_id}`；`factory.from_config(Config)` 按 `REVIVE_LLM__PROVIDER` 实例化；结构化输出：response_format 非空时解析失败自动重试 1 次（附报错回喂），仍失败抛 `LLMOutputError`；重试/退避/超时统一在适配层；`fake.py` 为回放式测试 Provider（按 prompt hash 返回录制响应）。
- 验收：`uv run pytest tests/unit/agents/test_llm.py -q` 绿，覆盖：三适配器构造、custom base_url 生效断言、API Key 缺失时报错不含 key 明文、`fake` 回放一致；`grep -rE "sk-[A-Za-z0-9]{20}" agents/` 无结果。
- 禁止：业务代码禁止 `import openai/anthropic`（只允许经 factory）；禁止把系统提示词硬编码进适配器。
- 依赖：T-CORE-01。

### T-AG-02 Prompt 注册表与输出契约测试
- 背景：所有提示词集中版本化（`prompts/<name>/vN.md`），带变量校验与 golden 测试，防止提示词漂移。
- 涉及文件：`agents/src/revive_agents/prompts/{registry.py,archaeologist/v1.md,repairer/v1.md,validator/v1.md}`、`tests/unit/agents/test_prompts.py`。
- 输入/输出契约：`render(name, version=None, **vars) -> list[Message]`；缺变量→`PromptVarsError` 列明缺失项；每个 v1 提示词文件末尾必须声明 `OUTPUT_CONTRACT: <schema 名>`；golden 测试：给定固定输入 + `fake` 回放，断言消息序列 hash 稳定。
- 验收：`uv run pytest tests/unit/agents/test_prompts.py -q` 绿。
- 禁止：禁止在节点代码里内联多行提示字符串。
- 依赖：T-AG-01。

### T-AG-03 Archaeologist Agent（考古补强节点）
- 背景：当 T-CORE-06 的 `overall_confidence < 0.7` 时，LLM 阅读 README/Issue 摘录/Dockerfile 原文补强推断；输出必须引用证据编号，禁止凭空报版本。
- 涉及文件：`agents/src/revive_agents/nodes/archaeologist.py`、`tests/unit/agents/test_archaeologist.py`。
- 输入/输出契约：输入 `{genome: EnvironmentGenome, low_confidence_fields: list[str], evidence_corpus: list[EvidenceItem]}`；输出复用 `environment-genome.schema.json`（仅允许提升 confidence / 追加 evidence，禁止删除原证据）；每条修改附 `llm_reason`；单元测试用 fake 回放 3 种情形：正确补强 / 幻觉版本（引用不存在的证据 id → 节点必须拒绝合并该修改并降级 warning）/ JSON 畸形（走 T-AG-01 重试后仍失败 → 原样返回输入 genome）。
- 验收：`uv run pytest tests/unit/agents/test_archaeologist.py -q` 绿，含"幻觉版本被拦截"显式断言。
- 禁止：不得调用网络（证据由上游注入）；不得修改 schema 外字段。
- 依赖：T-AG-02、T-CORE-06。

### T-AG-04 Repair Agent（补丁生成节点）
- 背景：消费 T-CORE-07 的 `ErrorFact` + 相关源码片段，产出 unified diff；这是唯一允许 LLM 改目标代码的节点，权限上限执行在此。
- 涉及文件：`agents/src/revive_agents/nodes/repairer.py`、`limits.py`、`tests/unit/agents/test_repairer.py`。
- 输入/输出契约：输入 `{error_fact, workspace_manifest: {path, sha256, lines} 白名单文件内容, prior_attempts: [PatchAttempt]}`；输出 `PatchProposal{diff: str, rationale, touched_files: list, lines_added, lines_removed, risk: low|medium|high}`；`limits.py` 常量 `MAX_ITERATIONS=5, MAX_FILES=10, MAX_LINES=300` 在此强制（超限→拒绝并返回 `Refused`）；diff 必须能被 `git apply --check`（在测试夹具工作区）通过才返回；py 文件改动过 `ast.parse` 语法校验；连续两次失败同 signature → 返回 `GiveUp` 触发 supervisor 终止该分支。
- 验收：`uv run pytest tests/unit/agents/test_repairer.py -q` 绿，含：超 300 行被拒、语法错误 diff 被拒、`collections.Mapping→collections.abc.Mapping` golden 案例（fake 回放）通过校验。
- 禁止：不得直接写文件（只产 diff，应用动作在沙箱流水线 T-SB-05）；不得提出改 `requirements` 之外的依赖版本升级"顺手现代化"（提示词+校验双重禁止）。
- 依赖：T-AG-02、T-CORE-07。

### T-AG-05 Behavior Agent（行为采集计划节点）
- 背景：判断"复生后还是不是原软件"需要可执行的行为用例。本节点从入口点/文档/示例生成运行计划与输入集，交给沙箱执行。
- 涉及文件：`agents/src/revive_agents/nodes/behavior_planner.py`、`tests/unit/agents/test_behavior_planner.py`。
- 输入/输出契约：输入 `{source_tree_summary, readme_excerpt, examples_dir?, tests_dir?}`；输出 `BehaviorPlan{cases: [Case{id, argv: list, stdin_file?, expect_files: list[glob], tolerance: {mode: exact|numeric|structural, eps?}}], budget: {max_cases: 25, timeout_per_case}]}`；已有测试目录时优先包装既有测试（引用 `pytest -k` 表达式）而非臆造；schema 外键为 0（pydantic 校验）。
- 验收：`uv run pytest tests/unit/agents/test_behavior_planner.py -q` 绿（fake 回放：`healthy-baseline` 夹具 → plan 至少包含 CLI `--help` 用例与既有测试包装）。
- 禁止：不得生成需要外网/真实凭据的用例（提示词声明 + 输出校验 argv 无 URL 白名单外域名）。
- 依赖：T-AG-02、T-CORE-08。

### T-AG-06 Supervisor 主图（LangGraph 全链路编排）
- 背景：把考古→建环境→构建→分类→修复→测试→行为→评分编排为带检查点的状态机，是产品的核心引擎。
- 涉及文件：`agents/src/revive_agents/graph/supervisor.py`、`graph/state.py`、`tests/unit/agents/test_supervisor.py`、`tests/integration/test_supervisor_smoke.py`。
- 输入/输出契约：状态 `GraphState{project, genome, sandbox_handle, build_attempts, error_facts, patches, behavior_plan, fingerprints, score, capsule_ref, iteration_counts}`；节点边：`analyze→infer→(archaeologist if low_conf)→build→{ok→tests→behavior→score→capsule | fail→classify→repairer→build}`；`build`/`tests` 等沙箱动作通过**依赖注入的 ExecutionPort 协议**调用（本工单定义 `ExecutionPort` 抽象：`ensure_env(genome) / run(kind, argv, timeout) / apply_patch(diff) / snapshot_ws() / restore_ws(token)`，实现在 T-SB 栈）；每个节点完成时发 `job-event.schema.json` 事件（经 `EventPort`，同样注入）；LangGraph checkpointer 用 Postgres（`langgraph-checkpoint-postgres`），thread_id=job_id；循环护栏：build 失败重试≤5、总事件数≤200、墙钟超时 `REVIVE_JOB__TIMEOUT`。
- 验收：单测（fake port 脚本化事件序列）：成功路径事件顺序 == 契约枚举顺序；失败路径恰好 5 次后 `job.failed` 且 payload.reason="repair_budget_exhausted"；`uv run pytest tests/unit/agents/test_supervisor.py tests/integration/test_supervisor_smoke.py -q` 绿（集成测试标记 `requires_docker`，无 Docker 环境自动 skip 并报 reason）。
- 禁止：supervisor 内不得出现 `requests/httpx` 出网调用；不得在节点里 sleep 轮询。
- 依赖：T-AG-03/04/05。

### T-AG-07 LLM 溯源与成本护栏
- 背景：生产系统必须能回答"这个补丁当时为什么这么改、花了多少钱"。
- 涉及文件：`agents/src/revive_agents/observability/tracing.py`、`budget.py`、`tests/unit/agents/test_budget.py`。
- 输入/输出契约：每次 LLM 调用记录 `{job_id, node, prompt_name/version, model, usage, latency, request_hash, response_hash}` 至 OTel span + 落 PG `llm_calls` 表（迁移属 T-BE-02，本工单只定义写入 Port）；`budget.py`：按 job 累计 `cost_usd_estimate`，超过 `REVIVE_LLM__JOB_BUDGET_USD`（默认 2.0）后 Provider 层直接抛 `BudgetExceeded` 并让 supervisor 走 `job.failed(reason="budget")`；日志脱敏：prompt/response 只存 hash，`REVIVE_DEBUG_LLM=1` 时才落全文（全文也须过密钥正则清洗）。
- 验收：`uv run pytest tests/unit/agents/test_budget.py -q` 绿（fake 计费到阈值触发）；`grep -l "response_hash" agents/src/revive_agents/observability/tracing.py` 存在。
- 禁止：禁止把完整 prompt 写入普通 logger（只准走 tracing）。
- 依赖：T-AG-01、T-AG-06。

### T-AG-08 证据记忆库（pgvector 检索辅助修复）
- 背景：历史修复案例是复生的复利资产。把 (ErrorFact.signature, 报错摘录, 最终生效 patch) 向量化入库，Repairer 生成前检索 top-3 相似案例注入提示词。
- 涉及文件：`agents/src/revive_agents/memory/{store.py,retriever.py}`、`tests/unit/agents/test_memory.py`。
- 输入/输出契约：`store.save_case(job_id, error_fact, patch, outcome)`；`retriever.similar(error_fact, k=3) -> list[Case]`；向量表 `swh_case_memory(id, signature, excerpt, embedding vector(1536), outcome, created_at)`——表由 T-BE-02 迁移创建，本工单只读写；embedding 供应商走 `REVIVE_LLM__EMBED_*`（未配置时功能自动降级为空检索并 info 日志——**修复主链路不得依赖记忆库**）；检索命中必须过滤 signature 大类不一致的样本。
- 验收：`uv run pytest tests/unit/agents/test_memory.py -q` 绿（sqlite+fake embedding 或 dockerless fake；真实 pg 集成测试标记 `requires_docker`）。
- 禁止：不得把用户私有仓库源码全文入库（只存 ≤2KB 摘录，许可证未确认的仓库摘录须打 `redistribute=false` 标记）。
- 依赖：T-CORE-07、T-AG-04。
