# ReviveOS Demo Runbook（真实数据约束）

任何数字必须引用真实 run_id；当前无真实结果，指标显示“待测”。

## 10 分钟现场流程
1. 0:00 提交已获许可的 fixture/repository，确认输入 commit。
2. 0:30 打开考古面板，展示证据来源，不声称成功率。
3. 2:00 切到预置事件流回放；网络故障时直接使用离线回放。
4. 5:00 打开行为对比页，缺失结果显示“待测”。
5. 8:00 下载 capsule，核对 manifest 与 run_id。
6. 9:30 展示 results JSONL、manifest、输入哈希审计链。

## 彩排检查
- [ ] 网络在线与断网各走一遍
- [ ] 所有数字可追溯到 results/<run_id>.jsonl
- [ ] 未运行格子显示待测
- [ ] 不把候选集当 pilot30
- [ ] 失败行和错误签名可见

## 桌面软件演示流程
启动桌面客户端 → 选择项目/commit → 点击“考古” → 检查证据时间线 → 点击“复生” → 观察沙箱阶段事件 → 打开行为验证 → 导出 capsule。客户端不可用时使用同一 run_id 的离线事件流回放；不得伪造事件。
